Работа выполнена в облачной копии ProKitchen. Папка Windows `C:\Users\salam\Desktop\CookAsistent2` отсюда недоступна и автоматически не изменяется.

## Исправления

- Защищённые страницы ждут восстановления сессии; обновление страницы не отправляет вошедшего пользователя на вход. Просроченный или повреждённый access token восстанавливается через refresh token. Редактор личного блюда также защищён маршрутом.
- Повторный запрос после обновления токена обрабатывает JSON и PDF одинаково с первоначальным запросом. Ошибка валидации после refresh не уничтожает действующую сессию.
- Стоимость калькулятора вычисляется из текущего состава: изменение порций меняет стоимость порции, а не стоимость всего набора ингредиентов. Добавление, удаление и изменение ингредиента сразу отражаются в результате. Повторное сохранение изменённого блюда обновляет запись без дубликата.
- Сервер самостоятельно пересчитывает суммы при создании и частичном изменении рецепта. Подмена сумм не сохраняется; нулевая цена разрешена; отрицательные количества, пустые названия и нецелые порции отклоняются.
- На мобильном экране заголовки калькулятора и редактора не перекрывают кнопки сохранения и удаления.
- Исправлены методы чтения и добавления связей ингредиентов с аллергенами; обновление списка связей применяется и проверяет существование аллергенов. Поиск русского названия блюда не зависит от регистра.
- Ошибки загрузки этикеток и аллергенов не подменяются успешным пустым результатом. При пустом справочнике нет утверждения об отсутствии аллергенов.
- Настройка уведомлений сохраняет состояние после перезагрузки. Удаление пользователя сразу убирает строку из административной таблицы.
- Исправлены устаревшие импорты, примеры компонентов, API поиска ингредиентов, передача ref кнопке подтверждения и ошибки TypeScript. Старые тесты клиента приведены к текущим компонентам и API.
- PDF использует реальную высоту текста: длинное название больше не перечёркивается разделителем, строки состава переносятся. Большой состав продолжается на следующих страницах с рамкой и подписью, без потери текста.

## Повторный запуск

Сначала `npm run setup` на закреплённых Node.js 22.20.0 / npm 10.9.3. Для обычной разработки — `npm run dev` из корня.

Для браузерных тестов установите Chromium командой `npx playwright install chromium` из `Front`, затем выполните `npm run test:smoke` из корня. В этой облачной среде используется системный Chromium:

```bash
export PATH=/workspace/.prokitchen-tools/node_modules/.bin:$PATH
export npm_config_cache=/workspace/.npm-cache
export PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium
npm run test:smoke
```

Тестовый запуск использует порты 3001 и 5175. Каждый размер экрана получает отдельную временную базу и процессы; рабочая база и обычный сервер на портах 3000/5173 не затрагиваются. Ограничители частоты запросов не отключаются. Тестовые учётные записи из `scripts/smoke-fixtures.cjs` создаются только в одноразовой базе. Выборочная проверка: `npm run test:smoke -- --grep 'register, reload'`.

## Ограничения проверки

- Линтер пока не проходит: 54 ошибки и 8 предупреждений, преимущественно `any`, доступность и зависимости React-хуков. Они не скрывались отключением правил.
- Внешняя пищевая ценность Spoonacular без отдельного ключа недоступна; эта интеграция не подтверждена.
- Проверен Chromium на Linux, включая эмуляцию мобильного размера. Запуск на Windows, Safari, физический принтер, старый набор браузерных тестов `Front/tests/e2e` и Storybook целиком не проверялись.
- Матрица работает с каталогом и зарегистрированными связями аллергенов. Состав личного блюда из калькулятора сам по себе не устанавливает наличие или отсутствие аллергенов.

Локальные секреты, базы данных, зависимости и временные результаты проверок не входят в изменения репозитория.
