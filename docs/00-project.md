# Паспорт проекта ProKitchen

## Название и происхождение

ProKitchen — ассистент повара. Собственный проект Саламатина Сергея, GitHub-профиль — https://github.com/gWalut. Работа выполняется индивидуально. Публичный репозиторий: https://github.com/gWalut/ProKitchen. Подготовка лабораторной находится в ветке lab-1 и включается в main через PR после согласования.

В коде сервера и старой документации также используются названия CookAssistant и cookassistant-backend. Основное название продукта — ProKitchen.

## Назначение и проблема

Приложение помогает повару рассчитывать себестоимость, сохранять состав блюд и формировать PDF-этикетки. Оно сокращает ручные расчёты стоимости ингредиентов и объединяет работу с рецептами, аллергенами и сохранёнными блюдами в одном интерфейсе.

Целевые пользователи — повара и сотрудники, которые ведут рецептуры. Администратор управляет пользователями и их правами.

## Роли и функции

Роли в коде — user и admin. Пользователь рассчитывает себестоимость, сохраняет свои блюда и получает этикетки. Администратор управляет пользователями и имеет расширенные права. Ограничения реализованы на сервере через JWT, проверки роли и владельца объекта.

Три основные функции:

1. Расчёт общей себестоимости блюда и стоимости порции по составу и количеству ингредиентов.
2. Сохранение и просмотр пользовательских блюд с составом и рассчитанной стоимостью.
3. Формирование PDF-этикеток для сохранённых блюд.

Основные сущности для объёма курса: пользователь, блюдо, ингредиент, аллерген. Состав блюда и связи ингредиентов с аллергенами образуют отношения этих сущностей; этикетка рассматривается как выходной документ. Окончательный объём согласуется с преподавателем в лабораторной работе 2.

## Стек и лицензия

Клиент: React 18, TypeScript, Vite 5, Tailwind CSS, React Router, TanStack Query. Сервер: Node.js, Express, JWT, Joi, PDFKit. Базовый локальный запуск использует SQLite. В коде также есть PostgreSQL и Compose/Nginx, но этот сценарий требует отдельной проверки. Для питательной ценности используется необязательный Spoonacular API.

Версия среды: Node.js 22.20.0, npm 10.9.3. Зависимости зафиксированы отдельными lock-файлами Front и Back. Авторский код распространяется под ISC, текст находится в LICENSE. Сторонние зависимости сохраняют собственные лицензии; лицензия шрифтов DejaVu находится в Back/fonts/LICENSE-DejaVu.txt.

| Front/src/shared | Общие элементы интерфейса, типы, контексты и хуки |
| Back/src/server.js | Запуск HTTP-сервера и завершение подключений |
| Back/src/app.js | Настройка Express, маршруты, CORS, health и обработка ошибок |
| Back/src/features | Серверные модули предметной области |
| Back/src/shared/database | Доступ к SQLite/PostgreSQL и SQLite-миграции |
| Back/src/shared/services | Расчёты и PDF |
| Back/src/config/config.js | Переменные окружения и настройки |
| Back/migrations | SQL-схема и последовательные изменения SQLite |
| Back/data | Локальная база; в Git не включается |
| Back/fonts | Шрифты для PDF с кириллицей |
| Back/tests | Модульные и интеграционные тесты сервера |
| Front/src/tests, Front/tests/e2e | Тесты клиента и браузерные сценарии |
| scripts | Установка, совместный запуск и изолированная проверка API |
| docs | Паспорт, документы курса, ADR, диаграммы и заготовки issues |
| src, tests в корне | Указатели на существующие каталоги кода и тестов |

Существующие Front/Back сохранены без переноса исходников. Такое соответствие рекомендуемой структуре курса следует согласовать с преподавателем.

Клиент обращается к относительному /api/v1. В разработке Vite проксирует /api на localhost:3000; в контейнерной конфигурации это делает Nginx. SQLite хранится в Back/data/kitchen.sqlite по умолчанию; DB_PATH позволяет задать отдельный файл. Back/.env создаётся командой setup и не включается в Git. Переменные процесса имеют приоритет над файлом. Корневой .env относится к существующей Docker-конфигурации и не используется локальной командой dev как файл настроек сервера.

| Работа с ингредиентами | Back/src/features/ingredients | После входа прочитать список и проверить изменение тестовой записи |
| Матрица аллергенов | Front/src/features/allergens; Back/src/features/allergens | Проверить таблицу для блюда с известными аллергенами |

В существующей базе при исходной проверке прикладные таблицы были пустыми. Каталог продуктов калькулятора задан в коде и доступен независимо от справочника БД. Для ручной проверки каталога и аллергенов нужны подготовленные тестовые данные. Не все функции из таблицы прошли полный ручной сценарий; протокол выполненных проверок находится в README.

## Журнал запуска

25 октября 2026 года выполнена исходная проверка на Windows с Node.js 22.20.0 и npm 10.9.3.

| Проблема | Принятое решение и статус |
| --- | --- |
| У Back отсутствовали зависимости | Добавлен единый setup с npm ci для Front и Back |
| Базовая миграция удаляла данные | DROP TABLE удалены из базовой схемы; добавлены транзакции, журнал миграций и контрольные суммы |
| После обычной миграции отсутствовала custom_dishes | В общий SQLite-сценарий включены миграции 001–003 |
| Health возвращал OK при недоступной БД | Добавлен реальный запрос к БД; при ошибке возвращается 503 |
| Импорт приложения запускал сервер и мешал тестам | Точка запуска вынесена в server.js |
| Тестовая база не имела схемы, оставались открытые ресурсы | Каждый набор получает новую БД с миграциями; подключения закрываются |
| Смена пароля выполнялась, но ответ содержал неопределённый result | Ответ исправлен; тест смены и отзыва токенов проходит |
| TypeScript, ESLint и старые тесты Front не проходят | Подготовлены bug-issues, исправление включается в последующие работы |
| Docker engine недоступен; PostgreSQL имеет расхождения SQL | Контейнерный сценарий не объявляется проверенным; подготовлен question-issue |

Полный запуск новой инструкции проверяется в отдельной папке без исходных node_modules, .env и SQLite-файла. Это проверка на том же Windows-компьютере; проверка на другой машине либо в чистой VM/контейнере ещё требуется.

## Выполнимость и план

Объём семестра: авторизация и две роли, расчёт себестоимости, сохранённые блюда, ингредиенты, аллергены, избранное, PDF и минимальное администрирование. Вне основного объёма: платная эксплуатация внешнего API, интеграции с кассами и поставщиками, складская ERP и полноценный производственный хостинг. Поддержка PostgreSQL требует отдельного решения.

| Риск | Вероятность | Последствия | Снижение |
| --- | --- | --- | --- |
| Расхождения SQLite/PostgreSQL | Высокая | Невоспроизводимый Docker-запуск | Подтвердить SQLite; PostgreSQL включать после отдельных миграций и тестов |
| Дефекты старого фронтенда и тестов | Высокая | Ошибки типов и неполные проверки | Исправлять по issues, проверять реальные пользовательские сценарии |
| Ошибки изменения схемы | Средняя | Повреждение или потеря данных | Транзакции, контрольные суммы, резервные копии и тесты сохранности |
| Ограничения Spoonacular | Средняя | Нет питательной ценности | Не делать внешний API обязательным для основной функции |
| Ограниченное время одного исполнителя | Средняя | Перегрузка и незавершённые функции | Зафиксировать границы, вести небольшой список задач и оценивать часы |
| Сторонние лицензии и отсутствие удалённого репозитория | Средняя | Проблемы оформления и проверки | ISC для авторского кода, сохранение сторонних уведомлений, настройка репозитория до сдачи |
