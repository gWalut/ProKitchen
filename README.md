# ProKitchen — ассистент повара

Собственный проект Саламатина Сергея (gWalut) для расчёта себестоимости, сохранения блюд и формирования PDF-этикеток. Роли пользователей — user и admin. Лицензия авторского кода — ISC.

## Запуск

Нужны Git, Node.js **22.20.0** и npm **10.9.3**, а также доступ к npm для первой установки. Версии указаны в .nvmrc, .node-version и package.json. Docker для базового локального сценария не нужен.

После получения чистого клона достаточно четырёх команд. Подставьте URL репозитория, когда он будет создан:

```powershell
git clone <URL-репозитория> ProKitchen
cd ProKitchen
npm run setup
npm run dev
```

Если папка уже есть, открыть её в терминале и выполнить последние две команды. setup устанавливает зависимости по lock-файлам Front и Back, создаёт Back/.env с отдельными случайными локальными секретами и применяет все SQLite-миграции. Существующий Back/.env не перезаписывается. Если в нём выбрана другая БД, установку нужно настроить отдельно: SQLite-миграции к PostgreSQL не применяются.

Открыть **http://127.0.0.1:5173**. API работает на порту 3000. Остановка обоих процессов — Ctrl+C в терминале запуска. Если порт занят, команда завершается с ошибкой; нужно остановить другой экземпляр, а не менять порт молча.

По умолчанию база находится в Back/data/kitchen.sqlite. Back/.env не включается в Git. Переменные окружения процесса имеют приоритет над этим файлом. Корневой .env относится к старой Docker-конфигурации и не подхватывается локальным сервером вместо Back/.env.

Миграции выполняются в транзакции и учитываются в schema_migrations. Повторный setup сохраняет существующие строки. Перед изменением рабочей схемы всё равно следует сделать резервную копию базы. Изменённый после применения файл миграции вызывает ошибку проверки контрольной суммы; новые изменения схемы оформляются следующей миграцией.

## Проверка работоспособности

1. Открыть http://127.0.0.1:5173/api/v1/health — ожидается HTTP 200 с status: ok и database: ok. При недоступной БД — 503.
2. Открыть калькулятор, добавить картофель 200 г по 0,05 ₽ и указать 2 порции: итог 10 ₽, за порцию 5 ₽.
3. Зарегистрировать тестового пользователя, сохранить блюдо и получить PDF-этикетку. Пустые списки на новой базе ожидаемы, пока данные не созданы.

Автоматическая проверка без изменения рабочей БД:

```powershell
npm run check
```

Она сама создаёт временную БД и HTTP-сервер на свободном порту, проверяет миграции, health, регистрацию, вход, ограничения доступа, сохранение блюда и сигнатуру PDF, затем закрывает сервер и удаляет свои временные данные. Установленные зависимости Back нужны и для этой команды. Визуальный вид PDF проверяется отдельно вручную.

## Команды проверки и сборки

| Команда из корня | Назначение и статус |
| --- | --- |
| npm test | Тесты сервера на отдельных временных базах |
| npm run check | Изолированная проверка основного API и PDF |
| npm run build | Сборка клиента в Front/dist |
| npm --prefix Front run type-check | Проверка типов, сейчас есть известные ошибки |
| npm --prefix Front run lint | Линтер, сейчас есть известные ошибки |
| npm --prefix Front test -- --runInBand | Старые тесты клиента, требуют обновления |

Успех сборки Vite не означает успех проверки TypeScript. Первоначальный анализ обнаружил 56 диагностик TypeScript, 68 ошибок и 8 предупреждений ESLint. Для тестов Front на обычной копии файлов обнаружены три набора: один прошёл, два не смогли запуститься. План исправлений — в docs/issues.

## Структура

Клиент — Front/src, точка входа main.tsx. Сервер — Back/src, точка запуска server.js; app.js экспортирует приложение без открытия порта. Миграции — Back/migrations, тесты сервера — Back/tests, клиента — Front/src/tests и Front/tests/e2e. Корневые scripts содержат setup, dev и check. Развёрнутая карта функций и архитектуры находится в docs/00-project.md.

## Docker и внешние сервисы

Compose с PostgreSQL и Nginx сохранён, но не является подтверждённой инструкцией запуска. В проекте остаются SQL и миграции, рассчитанные на SQLite; перед заявлением поддержки PostgreSQL нужно устранить расхождения и проверить Compose на чистых томах. Старые DOCKER-README.md и служебные PowerShell-скрипты могут содержать неактуальные предположения. Основная инструкция лабораторной — раздел «Запуск» выше.

Spoonacular для питательной ценности необязателен. Без SPOONACULAR_API_KEY виджет показывает недоступность сервиса, а расчёт себестоимости остаётся доступным. Ключи нельзя добавлять в Git.
