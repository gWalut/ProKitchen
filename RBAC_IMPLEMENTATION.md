# RBAC System Implementation - CookAssistant

## 📋 Обзор

Реализована система управления доступом на основе ролей (RBAC - Role-Based Access Control) для проекта CookAssistant.

## 🎭 Роли в системе

### 1. **GUEST (Гость)** - неавторизованный пользователь
- Доступ к публичной информации (список аллергенов, просмотр опубликованных блюд)
- Нет доступа к персональным данным

### 2. **USER (Пользователь)** - авторизованный пользователь
- Все возможности Guest +
- Управление собственными блюдами (создание, редактирование, удаление)
- Управление ингредиентами
- Калькулятор себестоимости
- Избранное
- Генерация этикеток

### 3. **ADMIN (Администратор)** - полный контроль
- Все возможности User +
- **Управление пользователями** (изменение ролей, удаление)
- Удаление любых ингредиентов
- Редактирование и удаление любых блюд
- Доступ к странице "Учет пользователей"

## 🔧 Backend Implementation

### Созданные файлы:

#### 1. **RBAC Middleware** - `Back/src/shared/middleware/rbac.middleware.js`
```javascript
- checkRole(allowedRoles) // Проверка роли пользователя
- checkOwnership(getResourceOwnerId) // Проверка владения ресурсом
- ROLES // Константы ролей
- isAdmin(user) // Проверка, является ли пользователь админом
- isOwnerOrAdmin(user, resourceOwnerId) // Комбинированная проверка
```

#### 2. **Admin Feature** - `Back/src/features/admin/`
- **admin.service.js** - бизнес-логика управления пользователями
- **admin.controller.js** - обработчики запросов
- **admin.routes.js** - маршруты API

#### 3. **Обновленные модели**
- **users.model.js** - добавлены методы:
  - `getAll()` - получить всех пользователей
  - `updateRole(id, role)` - изменить роль
  - `delete(id)` - удалить пользователя

### API Endpoints:

```
GET    /api/v1/admin/users              - Список пользователей (admin only)
GET    /api/v1/admin/users/:id          - Пользователь по ID (admin only)
PATCH  /api/v1/admin/users/:id/role     - Изменить роль (admin only)
DELETE /api/v1/admin/users/:id          - Удалить пользователя (admin only)
GET    /api/v1/admin/stats/users        - Статистика (admin only)
```

### Защищенные endpoints:

#### Ingredients:
- `DELETE /ingredients/:id` - **только admin**

#### Dishes:
- `PUT /dishes/:id` - **владелец или admin**
- `DELETE /dishes/:id` - **владелец или admin**

#### Custom Dishes:
- `PUT /custom-dishes/:id` - **владелец или admin**
- `DELETE /custom-dishes/:id` - **владелец или admin**

## 💻 Frontend Implementation

### Созданные компоненты и хуки:

#### 1. **Auth Hooks** - `Front/src/features/auth/hooks/`
- **useRole.ts** - хук для работы с ролями
  ```typescript
  const { role, isAdmin, isUser, hasRole, canAccess } = useRole();
  ```

#### 2. **RBAC Components** - `Front/src/features/auth/components/`
- **Can.tsx** - условный рендеринг на основе ролей
  ```tsx
  <Can roles={['admin']}>
    <button>Удалить</button>
  </Can>
  ```

- **ProtectedRoute.tsx** - защита маршрутов
  ```tsx
  <ProtectedRoute requiredRoles={['admin']}>
    <AdminPage />
  </ProtectedRoute>
  ```

#### 3. **Admin Feature** - `Front/src/features/admin/pages/`
- **AdminUsersPage.tsx** - страница управления пользователями
  - Таблица всех пользователей
  - Изменение ролей
  - Удаление пользователей

#### 4. **Обновленные страницы**
- **SettingsPage.tsx** - добавлена кнопка "Учет пользователей" (только для admin)
- **routes.tsx** - добавлен защищенный роут `/admin/users`

## 🧪 Как тестировать

### 1. Создание admin пользователя

Вручную в базе данных обновите роль:
```sql
UPDATE users SET role = 'admin' WHERE email = 'your-email@example.com';
```

### 2. Проверка Guest
1. Выйдите из системы
2. Попробуйте открыть /admin/users - должен редиректить
3. Попробуйте создать блюдо - требуется авторизация

### 3. Проверка User
1. Зарегистрируйтесь как новый пользователь
2. Создайте блюдо - должно работать
3. Попробуйте удалить ингредиент - получите 403 Forbidden
4. Попробуйте открыть /admin/users - должен редиректить
5. В настройках не должно быть кнопки "Учет пользователей"

### 4. Проверка Admin
1. Войдите как admin
2. Откройте Настройки → должна появиться кнопка "Учет пользователей"
3. Перейдите на страницу управления пользователями
4. Измените роль пользователя - должно работать
5. Попробуйте удалить пользователя - должно работать
6. Попробуйте удалить свою учетную запись - получите ошибку
7. Попробуйте изменить свою роль - получите ошибку
